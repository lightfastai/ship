# ship

This context names the concepts used to own bounded code-delivery outcomes without acquiring Target Project product authority.

## Language

**Shipping request**:
An Orchestration Request whose bounded objective is to deliver code to a Target Project-defined completion boundary.
_Avoid_: Programme, standing delivery mandate

**Code-delivery outcome**:
The bounded repository-native result that a Shipping Request asks `ship` to own.
_Avoid_: Ticket queue, phase completion

**Ordinary delivery effect**:
A code-delivery action routinely governed inside a Target Project, such as research, reversible design, editing, testing, review, integration, or tracker reconciliation.
_Avoid_: Blanket mutation authority

**Consequential effect**:
A deployment, production change, publication, release, migration, destructive action, paid execution, permission expansion, or comparable external effect requiring explicit Request inclusion and native approval.
_Avoid_: Implied shipping step

**Direct work**:
Delivery work performed by the root Orchestrator Session rather than through a Target Task.
_Avoid_: Untracked work

**Target task**:
A native Codex task opened in a Target Project for a bounded part of the Shipping Request.
_Avoid_: Orchestrator Delegation, mandatory worker

**Integrated result**:
The exact Target Project state at which its acceptance and integration boundary is evaluated.
_Avoid_: Reviewed pull-request head, implementation handoff

**Native delivery evidence**:
Authoritative Target Project records of work and outcome, including tasks, branches, commits, pull requests, checks, reviews, integration state, trackers, and in-scope deployments.
_Avoid_: Orchestrator checkpoint, copied work graph
