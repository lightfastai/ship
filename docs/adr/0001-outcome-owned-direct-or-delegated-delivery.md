# Own outcomes while choosing direct work or Target Task dispatch dynamically

`ship` owns one bounded code-delivery outcome, while the root Session may work directly or dispatch native Target Tasks when that creates real leverage. This deliberately rejects both a read-only root/worker choreography and a registered-programme engine: mandatory delegation adds overhead to coherent changes, while root-only execution loses useful isolation and parallelism. Target Project rules and native evidence govern either strategy, and the root retains terminal accountability.
